> 日期：2026-08-01

> 范围：为文章详情页增加同一文章类型内的上一篇、下一篇导航；本文件是实施计划，不包含功能代码改动。

## 一、需求与当前基线

### 1.1 用户需求

在文章详情页的操作区（收藏、编辑）下方固定增加两行：

- `上一篇文章：文章标题`
- `下一篇文章：文章标题`

存在相邻文章时，标题必须是可点击的站内超链接，点击后进入对应文章详情页；没有上一篇或下一篇时，保留对应行的说明，但该行不得渲染链接、`href` 或点击跳转行为。

### 1.2 已核实的实现现状

| 层次 | 当前事实 | 本迭代影响 |
|---|---|---|
| 详情接口 | `GET /api/articles/{id}` 由 `ArticleController::get` 返回 `article.toJson()` | 在不改变 URL 的前提下扩展返回数据 |
| 页面 | `frontend/src/views/ArticleDetail.vue` 只请求一次详情，操作区仅有收藏与条件性“编辑”按钮 | 在该操作区下方增加语义化导航块 |
| 路由 | 已存在 `ArticleDetail` 路由：`/article/:id`，并监听 `route.params.id` 重新拉取详情 | 直接复用现有路由，不能整页刷新 |
| 数据模型 | `article` 有 `type`、自增主键 `articleid`、`hidden`、`drafted`，没有文章专用排序列 | 不做迁移；以 `articleid` 定义本期“序号” |
| 当前公开可见规则 | 文章列表使用 `hidden = 0 AND drafted = 0` | 导航候选必须复用该规则，避免把隐藏/草稿文章暴露为链接 |

## 二、产品与数据契约决策

### 2.1 “同一个文章类型里面的序号”的定义

本期将**同一 `type` 下的 `articleid` 升序**定义为文章序号：

- `上一篇`：同一 `type` 内、`articleid` 小于当前文章的最大一篇；
- `下一篇`：同一 `type` 内、`articleid` 大于当前文章的最小一篇；
- 两个方向均只在 `hidden = 0 AND drafted = 0` 的公开文章集合中查找；
- 不以 `createtime` 排序，避免同秒创建时顺序不确定；不增加 `checked` 过滤，以保持与现有公开列表一致的可见性语义。

这项定义以当前表中可用的、稳定且唯一的自增序号为依据。若未来需要运营人员自定义系列文章顺序，应另立迭代引入 `sort_order` 等显式排序字段；不得在本迭代中偷偷改变排序规则。

### 2.2 详情响应扩展（兼容既有调用方）

不新建第二个导航接口，也不改变 `GET /api/articles/{id}` 的已有字段。详情数据新增可选但本期始终返回的 `navigation` 对象：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "articleid": 102,
    "type": 701,
    "headline": "当前文章",
    "navigation": {
      "previous": { "articleid": 101, "headline": "上一篇标题" },
      "next": { "articleid": 103, "headline": "下一篇标题" }
    }
  }
}
```

边界情形使用 JSON `null`，不使用虚假 ID、空对象或空链接：

```json
"navigation": {
  "previous": null,
  "next": null
}
```

字段只包含渲染和跳转必需的 `articleid` 与 `headline`，不返回相邻文章正文、作者、积分或隐藏状态。新增字段对现有客户端是向后兼容的；`articleApi.getDetail(id)` 的调用方式保持不变。

### 2.3 页面交互契约

在 `.article-footer` 的 `.article-actions` **之后**加入：

```text
上一篇文章：<上一标题链接或“暂无上一篇文章”纯文本>
下一篇文章：<下一标题链接或“暂无下一篇文章”纯文本>
```

- 使用 Vue `<router-link>` 指向 `{ name: 'ArticleDetail', params: { id } }`，不使用 `window.location` 或裸外链；
- 两行始终可见，标题由 `headline` 插值渲染，不注入 HTML；
- 某方向为 `null`（或旧服务暂未返回 `navigation`）时，使用普通 `<span>` 显示“暂无上一篇文章”/“暂无下一篇文章”；DOM 中不得存在该方向的 `<a>`、`href` 或 `@click`；
- 点击有效链接后由既有 `route.params.id` watch 重新加载标题、正文、评论、收藏状态和新的导航数据；
- 链接需要有清晰的 hover/focus 样式、可见焦点，以及小屏换行与长标题截断/换行策略，不能挤压正文或侧栏。

## 三、实施拆解

### Epic 15.1：详情接口提供同类型导航数据（P0）

**责任文件**

- `backend_cpp/controllers/ArticleController.cc`
- `backend_cpp/controllers/ArticleController.h`（仅在需要补充响应契约说明时）

**实施任务**

1. 保持 `ArticleController::get` 的“按 ID 找当前文章、找不到返回 404、详情访问加一次 `readcount`”主流程不变。
2. 当前文章查询成功后，以其 `type` 和 `articleid` 查询两个方向的最邻近公开文章；查询结果只投影 `articleid, headline`。
3. `previous` 使用 `articleid < currentId ORDER BY articleid DESC LIMIT 1`，`next` 使用 `articleid > currentId ORDER BY articleid ASC LIMIT 1`；每个查询都带同样的 `type`、`hidden = 0`、`drafted = 0` 条件。
4. 在 `article.toJson()` 生成的详情对象上设置 `navigation.previous` 与 `navigation.next`，缺失方向显式写入 JSON `null` 后再响应。
5. 导航查询若发生数据库异常，记录可检索的 warning，并以两个 `null` 作为降级结果返回已找到的当前文章；当前文章查询本身失败仍维持现有 500 行为。这样不会因为可选导航让已可读的文章详情不可用，也不会生成错误跳转。
6. 不修改 `models::Article` 的持久化字段，不新增数据库列、迁移或第二个 HTTP 请求。发布前在代表性数据上执行 `EXPLAIN`；只有明确证明现有 `idx_type` 与主键无法满足响应目标时，才单独评审复合索引迁移。

**验收标准**

- 中间文章只得到同 `type`、相邻 ID 的上一/下一文章；其他分类、隐藏文章、草稿文章均不会出现。
- 第一篇 `previous` 为 `null`，最后一篇 `next` 为 `null`，仅有一篇公开文章时两者均为 `null`。
- 详情原有字段、HTTP 404、响应包络和 `readcount` 行为不回归。
- 新字段不包含正文或其他不必要敏感信息。

### Epic 15.2：文章详情页渲染与站内跳转（P0）

**责任文件**

- `frontend/src/views/ArticleDetail.vue`
- `frontend/src/views/ArticleDetail.spec.js`
- `frontend/src/api/index.js`（仅确认 `getDetail` 无需增加新包装器）

**实施任务**

1. 从详情响应的 `article.navigation` 安全读取 `previous` 与 `next`，对缺少该字段的旧响应降级为两个 `null`。
2. 在操作按钮下添加 `<nav aria-label="同类文章导航">`，用两个独立行承载“上一篇文章”和“下一篇文章”。
3. 有候选时渲染 `<router-link>` 与文章标题；无候选时只渲染禁跳转的普通文本，不把禁用状态伪装成可点链接。
4. 补充局部 scoped CSS：导航与编辑按钮的间距、标题最大宽度、长标题溢出行为、hover/focus、键盘焦点和 `max-width: 768px` 下的纵向布局。
5. 复用现有路由参数监听；确认文章间连续点击时不会遗留上一页的标题、导航、收藏或评论数据。

**验收标准**

- 登录/未登录、显示/不显示编辑按钮均可看到两行导航。
- 有相邻文章时标题是可用的 `/article/{id}` 站内链接；点击后 URL、浏览器标题与正文变为目标文章。
- 无相邻文章时对应行没有链接元素，也不能通过鼠标、键盘或程序化点击进入其他文章。
- 文章标题中的特殊字符按 Vue 文本插值显示，不作为 HTML 执行。

3. 在 `ArticleDetail.spec.js` 中覆盖：双链接渲染、单边缺失时无锚点、旧响应缺少 `navigation` 时的安全降级、路由 ID 改变后导航重新计算。

## 六、范围边界、风险与决策记录

### 本迭代不做

- 不为文章添加人工排序、系列、章节或跨分类导航；
- 不修改遗留 Flask 后端；
- 不改变文章详情的鉴权、积分、收藏、评论和阅读计数规则；
- 不新增独立导航 API、缓存层或数据库迁移。

### 风险与应对

| 风险 | 应对 |
|---|---|
| “序号”未来被理解为人工排序 | 本期文档和测试锁定为 `articleid`；自定义顺序另立数据模型迭代 |
| 导航查询误把非公开文章暴露出来 | 两个方向使用与公开列表一致的 `hidden/drafted` 谓词，并用真实集成测试覆盖 |
| 详情接口扩展影响旧客户端 | 只追加 `navigation` 字段，不删除/重命名既有字段；前端对字段缺失降级 |
| 数据量增长造成邻居查询变慢 | 先用 `EXPLAIN` 留存证据；复合索引须作为独立、可回滚的数据库变更评审 |
| 无邻居仍表现得可点击 | 以条件渲染去除 `<router-link>`，而非 CSS 禁用链接 |

## 七、完成定义（Definition of Done）

1. 当前 C++ 详情接口稳定返回符合本文件定义的 `navigation` 数据；
2. Vue 详情页在编辑/操作区下方显示两行导航，存在时可跳转、不存在时无链接；
3. 同类型、序号、可见性、首尾边界和连续路由跳转都有自动化覆盖；
4. 前端 lint、单测、构建、E2E，C++ CTest 与后端 HTTP 集成测试均有本次执行证据；
5. 不产生数据库迁移、遗留 Flask 改动或与本功能无关的工作区修改。
