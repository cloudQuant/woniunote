### F17-1：函数覆盖是主短板（65.04%），且两类缺口性质不同

### F17-2：分支覆盖 85.61%，缺口集中在错误路径与条件渲染

129 个未覆盖分支主要分布在：API 失败/空态分支（列表组件）、表单校验失败路径（Register/Profile/WriteArticle）、条件渲染（登录态切换、权限差异）、MathQuestion 的答题判定分支（33.3%，最突出）。

### 计划外修复：写文章页内容同步静默失效（CRITICAL）

**现象**（17.5 的 E2E 发现）：新文章无法发布——点击发布始终提示"请输入内容"；导入的 Markdown 也不进表单；手动编辑内容在保存时静默丢失。

**诊断过程**（逐层证伪）：

1. E2E 首诊认为是 `contentChange` vs `contentchange` 大小写不匹配——**证伪**：`getListener` 内部 `type.toLowerCase()`，事件名大小写不敏感。
2. 浏览器探针实测：此 UEditor 构建只在 setContent/execCommand/插件操作时触发 contentchange（导入触发 2 次），**普通打字 0 次**；且 UEditor 的事件代理列表不含原生 `input` 事件。
3. 继续探针：组件注册的 ready 回调**从未执行**，同时存在未捕获 `TypeError: Cannot read properties of undefined (reading 'join')`。
4. **根因**：本仓库的 UEditor 构建把 `imageAllowFiles` 默认值裁剪掉了；simpleupload 插件的 ready 监听器执行 `getOpt('imageAllowFiles').join(',')` 时抛异常。而 UEditor 的 `fireEvent` **没有异常隔离**——一个监听器抛异常即中断整个事件分发，导致后注册的插件先执行、先注册的组件回调（逆序遍历最后执行）永远不被调用。内容同步、主题注入、ready 事件全部静默失效。

**修复**（`UEditor.vue`，四层）：

- 配置显式补齐 `imageAllowFiles`（消除已知异常源）；
- 编辑器 iframe body 上绑定**原生 `input` 事件**（覆盖打字/粘贴等所有用户编辑，300ms 防抖）——UEditor 不代理 input 事件，仅靠 contentchange 无法覆盖打字；
- `blur` 时冲刷防抖队列（保证点击"发布"前的最后一次编辑已同步）；
- `isReady` 轮询兜底初始化（防御未来其他插件异常再次中断 ready 分发）。

**验证**：发布用例从超时失败转为 1.6s 通过；E2E 60/60 全绿。

1. `MathHistory.vue:46` — `row.accuracy.toFixed(1)` 无空值保护，后端缺字段时整表渲染失败。
2. `useMathTraining.js` — `formatTime` 的 try/catch 为死代码（`new Date(undefined)` 返回 "Invalid Date" 而非抛异常）。
3. `useArticleRendering.js:104` — PDF 链接选择器 `a[href$=".pdf"]` 不匹配带查询串的链接。
4. `Register.vue` / `Profile.vue` / 用户侧视图多处 catch 仅打日志、无用户提示（保存/注册失败时用户无感知）。
5. `ArticleCategoryCenter.vue` — `batchChangeType` 部分失败时不刷新列表，前端状态与后端不一致。
6. `api/index.js` — 业务码失败且无 message 时，reject 的 error.message 与 toast 提示不一致。
7. `/edit/:id` 编辑模式编辑器不回填内容（form.content 正确，但编辑器 iframe 显示为空，作者盲编辑）——与本次修复同一组件，建议后续迭代验证修复。
