# 迭代 7：代码质量加固与功能完善方案

> 作者：BMad Help（基于 woniunote 代码现状分析）
> 日期：2026-05-30
> 分支：dev_cpp（C++ Drogon 后端 + Vue3 前端）
> 范围：安全加固、前后端接口对齐、缺失功能补全、测试体系搭建

---

## 一、背景与现状

WoniuNote 已完成从 Python Flask 到 C++ Drogon + Vue3 的架构迁移，核心功能（文章 CRUD、评论、收藏、登录注册、数学训练、管理后台）已可用。但经过对 `backend_cpp/`、`frontend/src/`、`tests/` 及旧 Flask 应用（`build/lib/woniunote/`）的逐文件分析，发现以下系统性问题：

- **安全隐患**：SQL 注入、明文凭据入库、CORS 白名单形同虚设、跨平台密码哈希不兼容
- **健壮性缺陷**：参数解析无校验会导致进程异常、部分异常回调不触发导致请求永久挂起
- **前后端接口大量不匹配**：8+ 处前端 API 路径与后端实际路由不一致，相关功能直接失效
- **功能缺口**：相比旧版，卡片中心、待办中心、草稿箱、付费阅读、楼中楼回复等功能缺失或未完成
- **测试覆盖为 0**：旧 Python 测试无法运行于新栈，新后端/前端无任何测试

本迭代按"先止血、再对齐、后补全、最后固化"的顺序推进。

## 二、问题清单（含证据）

### P0 — 安全与崩溃风险（必须优先）

| 编号 | 问题 | 证据 | 影响 |
|------|------|------|------|
| S1 | 文章搜索 `keyword` 直接字符串拼接进 SQL | `ArticleController.cc:76-77` | SQL 注入，可拖库/绕过 |
| S2 | `page/page_size/type` 直接 `std::stoi`，非数字输入抛异常无捕获 | `ArticleController.cc:52-60` | 恶意参数触发进程级异常 → 拒绝服务 |
| S3 | `config.json` 提交了真实数据库密码与弱 JWT 密钥 | `config.json:71`、`config.json:84`；`config.cc:31` 默认弱密钥 | 凭据泄露 |
| S4 | 跨平台密码哈希不一致：Linux 用真 bcrypt，macOS 回退 SHA256 自制哈希 | `security.cc:84-103` | 开发机与生产哈希互不兼容，用户无法登录 |
| S5 | CORS 全局回显任意 Origin 且 `Allow-Credentials=true`，白名单 `cors_origins` 从未生效 | `main.cc:38-46`、`CorsFilter.cc:23`、`config.cc:50-55` | CSRF/跨站凭据风险 |
| S6 | `getHot` 内层 DB 异常回调只记日志、不调用 `callback` | `ArticleController.cc:191-199` | DB 出错时请求永久挂起至超时 |
| S7 | `toggleRecommend/toggleHide` 二次查询空结果直接 `result[0]` | `ArticleController.cc:436、479` | 越界崩溃 |
| S8 | `beginTransaction` 失败分支不回调 | `database.cc:55-58` | 调用方回调永不触发，请求挂起 |

### P1 — 前后端接口对齐与一致性

后端实际路由 vs 前端 `api/index.js` 调用对照（已核实路由表）：

| 前端调用 | 前端路径 | 后端实际路径 | 状态 |
|----------|----------|--------------|------|
| `commentApi.agree/oppose` | `/comments/{id}/agree`、`/oppose` | `/comments/{id}/vote` | 不匹配，点赞失效 |
| `commentApi.update` | `PUT /comments/{id}` | 无 | 后端缺失 |
| `userApi.updateProfile` | `PUT /users/me` | `PUT /users/profile` | 不匹配 |
| `userApi.updatePassword` | `PUT /users/me/password` | `POST /users/password` | 路径+方法均不符 |
| `creditApi.getList` | `/credits` | `/credits/history` | 不匹配 |
| `creditApi.getSummary` | `/credits/summary` | `/credits/balance` | 不匹配 |
| `creditApi.payArticle/checkArticle` | `/credits/pay-article/{id}` 等 | 无 | 后端缺失 |
| `draftApi.getMyDrafts` | `/articles/drafts/my` | 无 | 后端缺失 |
| `myCommentApi.getMyComments` | `/comments/my` | 无 | 后端缺失 |
| `adminApi.toggleCheck` | `/articles/{id}/check` | 无（仅 recommend/hide） | 后端缺失 |
| `systemApi.getMetrics/getProcesses` | `/system/metrics`、`/processes` | 仅 health/status/db | 后端缺失 |

其它一致性问题：
- 错误响应不统一：`AuthController` 有 `makeJsonResponse/makeErrorResponse` 并设置 HTTP 状态码（`AuthController.cc:23-45`），`ArticleController/CommentController` 手写 JSON 且**多数不调用 `setStatusCode``，与前端拦截器基于 HTTP status 的 401/403/404 分支冲突（`api/index.js:80-94`）。
- 登录未校验验证码（`AuthController.cc:155-157` 仍是 TODO），`CaptchaController` 已存在但未接入。
- `refresh_token` 机制前端已封装但 401 时直接登出，从未做无感刷新（`api/index.js:81-86`）。
- `RateLimitFilter` 未挂载到任何路由，且 Redis 不可用时 fail-open（`RateLimitFilter.cc:35-40`），限流实际未启用。

### P2 — 功能缺口（对比旧 Flask）

| 功能 | 旧版位置 | 新版状态 |
|------|----------|----------|
| 卡片中心 Card Center（~13 路由） | `card_center.py`、`models/card.py` | 完全缺失 |
| 待办中心 Todo Center | `todo_center.py`、`models/todo.py` | 完全缺失 |
| 草稿箱 | `/user/draft` | 前端有页面，后端无路由 |
| 我的评论列表 | `/user/comment` | 前端有页面，后端无路由 |
| 付费阅读（积分支付看文章） | `article.read` + credit | 前端有调用，后端缺失 |
| 楼中楼评论回复 | `/reply` + replyid | create 存了 replyid 但无树状返回 |
| 文章审核 check 状态 | `/admin/article/check` | 后端无 check 路由 |
| 系统监控大盘 | 丰富指标 | 仅 health/status/db |

### P3 — 工程质量

- C++ 后端零单元测试（`backend_cpp/tests/` 仅 README，无 CMakeLists.txt）。
- 前端无测试框架（`package.json` 无 test 脚本）。
- 旧 Python 测试 import `woniunote.*` 依赖 Flask 上下文，无法用于新栈。
- Controller 样板代码大量重复（`Json::Value ret; ret["code"]=...` 模式遍布）。
- 注册（user + credit 两条 INSERT）、评论计数更新非原子，无事务保护。
- 全局 `log_level=DEBUG`（`config.json:55`），INFO 日志打印 username/IP，生产信息泄露。

## 三、迭代目标

1. **零高危安全问题**：消除 SQL 注入、凭据泄露、CORS 失控、哈希不兼容。
2. **前后端接口 100% 对齐**：所有前端调用都能命中真实后端路由。
3. **核心缺失功能补全**：草稿箱、我的评论、付费阅读、楼中楼回复、登录验证码。
4. **测试体系从 0 到 1**：C++ 后端关键路径单测 + 前端关键组件测试，CI 可运行。
5. **统一工程规范**：统一错误响应、引入事务、收敛日志级别。

### 部署注意（重要）

由于移除了入库的明文密码，运行前端/后端前需提供真实凭据：
1. **数据库密码**：在本地 `config.json` 或生产 `config.prod.json` 的 `db_clients[].passwd` 填入真实值（生产建议用未入库的 `config.local.json`，已加入 `.gitignore`）。
2. **JWT 密钥**：设置环境变量 `WONIUNOTE_JWT_SECRET` 为强随机值（优先级高于配置文件）。
3. 已泄露的旧密码 `Woniunote_password1!` 应在数据库侧轮换。
