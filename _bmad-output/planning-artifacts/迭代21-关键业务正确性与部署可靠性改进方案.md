### 21.1 登录入口与 refresh/退出一致性（P1）

**拥有路径：**`frontend/src/views/Login.vue`、`Register.vue`、`WriteArticle.vue` 的重新认证前编辑恢复、`components/layout/AppHeader.vue`、`stores/user.js`、`api/index.js` 及对应测试；`backend_cpp/controllers/AuthController.{h,cc}`、`core/security.*`，必要的令牌 payload/过滤器调整。注册段与 21.2 串行整合；不为每个 access 请求新增 Redis 查询。

1. 两入口统一用户名/验证码契约；失败后刷新已消费 challenge、保留用户名及错误。修复 Header 仅接受邮箱的差异（`AppHeader.vue:219–226`）和注册后丢失 redirect（`Register.vue:126–132`）。redirect 仅接受可解析的站内目标，拒绝外部 URL、协议相对 URL 及登录/注册自循环；新版客户端跳转登录前保留当前用户的编辑快照，重新认证后仅向同一用户提供恢复，不跨账号显示，按 AC21-15 验证。
2. 将本地清理与主动退出拆开；退出开始即使当前客户端会话代际失效，使用捕获凭据调用 logout，最终无论网络结果都清理对应本地状态。logout 排除自动 refresh；401、`refreshUserInfo` 失败和清理队列只做本地失效，不能递归调用撤销 API。
3. token 写回、用户资料写回、401 清理与排队请求重放均校验发起时的会话代际/凭据快照：晚到 refresh 不恢复已退出状态，旧失败不清除新登录，旧请求不以新身份重放。跨标签共享存储同样测试；本轮可在竞争失败时要求重新登录，不承诺多标签无感刷新。
4. 按 D01 原子比较 `(sid, old_jti)`、轮换 JTI 和更新 TTL，按 D02 原子比较 sid 退出。refresh TTL 延续现有滑动期限，精确取令牌剩余有效期且必须为正；sid 使用安全随机源，失败拒绝签发。无记录、旧格式、错误类型/签名/过期 refresh 均拒绝，不静默降级。
5. 线性化以 Redis 命令执行顺序为准：logout 先执行则 refresh 失败；refresh 先执行则后续同 sid logout 撤销其新 JTI；新登录产生新 sid，旧 logout 不删除它。并发登录以最后成功写入的 sid 为准，不以 HTTP 返回先后判胜。
6. Redis 写入已执行但确认丢失/超时后完成时，503 只表示未知，客户端不得自动重复轮换，提示重新登录；不能无条件 DEL 补偿。设置应用层一次性完成保护及有界依赖超时，验证晚到回调不会二次响应，记录未知结果但不记录原始 token。

|---|---|
| AC21-01 | 两入口分别用普通用户名/邮箱式用户名完成真实登录；验证码缺失、错误、过期、复用均拒绝，错误尝试后的消费规则一致；受保护页→登录→注册→登录能回到原目标，非法 redirect 不出站/循环 |
| AC21-02 | 主动退出调用 API，完成后所属 sid 的 refresh 不再有效；重复退出、已被新登录替代、access 过期而 refresh 有效及凭据身份冲突按 D02 处理。网络失败清理本地并提示未确认，access 剩余 TTL 不误称即时失效 |

### 21.2 注册与训练写入一致性、输入边界（P1）

**拥有路径：**`AuthController.cc` 注册段、`MathTrainingController.cc`、`models/MathTraining.*`、`scripts/sql/08_math_training.sql` 及增量迁移、`frontend/src/composables/useMathTraining.js` 和对应展示/测试；必要的 `core/database.*` 小范围辅助。不进行所有控制器重构。

- 注册用户/初始积分及训练主记录/错题分别同事务，只有确认 commit 后响应成功。事务获取失败、SQL 失败、回滚、commit 失败/确认丢失、连接中断、迟到回调均须在配置期限内完成且只响应一次；该完成契约同样适用于 21.3 投票。事务完成回调不能强持有自身而阻止释放/提交。

- 客户端不自动重放未知结果的写请求：注册可提示尝试正常登录；训练保留本次结果快照并提示核实历史记录，投票重新读取计数。用户明确再次提交可能产生重复训练，本轮不承诺请求级 exactly-once；如要求无损自动重试，须另批幂等键范围并重估。

### 21.3 评论、公开资料与过滤器边界（P1）

### 21.4 构建失败保护、静态资源切换与回滚（P1）

**拥有路径：**`start_app.sh`、`restart_app.sh`、`scripts/setup_ubuntu.sh` 的部署交接、`configs/woniunote_nginx_prod.conf`、部署说明及隔离演练脚本；仅在资源寻址确需变化时修改前端构建配置。初始化脚本不得作为绕过保护的在线升级入口，不顺带重写操作系统安装流程。

- 候选来自已冻结 SHA 的独立源码目录，按锁文件安装依赖、使用独立前后端构建目录；不得沿用在线 `node_modules`、在在线工作区 `git pull` 后覆盖构建，或在候选完成前停止服务/删除 dist。记录 SHA、构建参数、前后端产物摘要和资源清单；依赖安装、产物缺失、Nginx 校验/reload 失败均须非零退出，不能只打印警告。
- 生命周期固定为“准备→验证→取得部署锁→切换→Nginx 入口冒烟→确认”；失败进入“恢复→复验”。同一目标只允许一个部署/清理任务，切换前重新核对当前版本。记录上一版本、配置和切换阶段；中断后可确定恢复位置，不靠猜测 symlink 状态。
- 版本化前端目录与原子入口切换之外，旧 `/assets/<hash>` 必须继续可寻址。默认采用只追加 hash 资源及每版资源清单，或通过等价方案证明可达；同名不同内容拒绝覆盖。保留“当前版 + 可回滚版 + 最近退役未满 7 天的所有版本”所引用资源，窗口从最后停止提供该版 index 起算，回滚重新激活后重置；不能仅保留最近两个版本。
- index/SPA fallback 使用 `no-cache` 并验证条件请求；只有内容寻址资源使用长期 immutable。盘点 `public` 下非 hash 的 UEditor 脚本等文件，采用重新验证或版本化 URL，不让新旧页面共用被覆盖的不兼容脚本。当前 PDF worker 内联打包（`frontend/src/components/viewer/PdfViewer.vue:74–82`），不把未使用的独立 worker 路由当作必须重构的功能。
- 切换单元包含后端二进制、前端入口、Nginx 配置及运行配置引用；**上传/缩略图、密钥和日志属于共享持久状态，不进入版本目录清理**。显式指定后端配置与工作目录，避免 `config.local.json` 自动优先于预期配置（`backend_cpp/main.cc:24–36`）。候选配置先独立 `nginx -t`，保留原配置；reload 失败恢复原文件并验证旧入口，不能破坏下次重启。
- 本轮默认允许短暂后端重启，不承诺零停机；记录 drain/停止超时、切换超时和恢复时长预算，批准 D04 后作为门禁。迁移写入冻结、兼容性和回滚按 21.3 执行；保留旧二进制不代表旧代码可安全读新 schema/新会话格式。
- **首次升级过渡单列：**旧客户端基线为 `v2.0.0`（`f2aaec6…`）及本文审查 SHA，已有页面没有完整的编辑恢复能力，新代码不能追补已加载旧页面。切换 sid 格式前通知并确认正在编辑的用户已保存/导出内容、关闭编辑页；上线后重新打开新版并登录。无法确认时默认延期，若负责人仍决定切换，必须记录受影响版本/用户、未保存内容可能丢失的风险及一次性豁免；该保护项记 GAP，不宣称通过，也不自动沿用到后续升级。
- 后续升级以具备编辑恢复能力的迭代 21 前端候选为基线，验证“旧前端→新后端”和“新前端→回滚后端”。认证/资料/训练请求在窗口内兼容，或明确要求刷新/重新登录并由 21.1 的新版客户端恢复同用户编辑；窗口外只提示一次，不无限刷新。原始 v2.0.0 后端的已知缺陷或训练不兼容只允许作为应急降级，不能借其回滚冒充正常业务门禁通过。

### 21.5 真实业务回归与最终验收（P1，贯穿开发，最后汇总）

- 保留 mock E2E 的四个项目（Chromium、Firefox、WebKit、移动 Chromium，不称为四种浏览器引擎）；未知 API 请求记录 method/URL 并在测试结束时断言为零，不能仅返回 500 后被页面忽略。已知可选请求显式登记，补齐登录/退出/投票/训练的响应和错误码契约。

### 21.6 封面上传、存储、编辑与回读（P1，真实失败驱动的必要增量）

1. 共享最小封面值校验与 DTO 规范化规则：只允许 ASCII 字母、数字、下划线、横线、点及路径分隔符；拒绝空段、`.`/`..` 及任何 `..` 子串、反斜杠、百分号编码、空白/控制字符、query/hash、协议相对及外部/data URL。文件名须有非空扩展名；不把输入当任意文件系统路径。空或无效历史值在 DTO 回退类型默认图，不迁移或删除历史正文/文件。
2. 创建与编辑都持久化封面；更新省略 thumbnail 时由 SQL 保持当前列，避免先读旧值再覆盖并发封面更新。保留所有权、drafted 和现有会话/表单身份语义。卡片和编辑预览正确解析上传 URL 与旧文件名；仅展示层添加静态封面缓存参数，不能写回数据库。
3. 新库基础 SQL 与升级迁移统一为 nullable VARCHAR(512)。迁移保持 NULL/空/旧值以及原字段字符集、排序规则，不缩列、不截断；缺列、未知类型/宽度/可空性须明确失败。已有库显式备份、预检后迁移；安装入口发现不兼容时停止，不忽略后启动一个无法写入封面的服务。
4. 真实 UI 必须执行原有上传→保存草稿→再次编辑并更换另一张有效图片→发布→匿名正文/卡片读取，以及既有评论/投票链路；核对响应 URL、实际图片加载及原字节。保留 source17 失败，不删除封面步骤、不弱化 200/MIME/字节断言。
5. 首次升级纳入封面迁移；正常升级/回滚只使用已证明兼容该 URL/schema 的冻结候选，运行数据不随版本清理。原始 v2 对新媒体值的读取不兼容须披露，不伪称原始版正常回滚通过。生命周期隔离和两类上传校验继续执行。

**AC21-19：**真实 HTTP 和独立持久化读取证明创建、详细/列表 DTO、编辑更换、省略保持、显式空及非所有者拒绝符合 D07；非法类型/路径/超长不写入。旧库升级/重跑/新库一致、NULL/旧值及字符集保留、未知形状拒绝有隔离 MySQL 证据。前端单测与真实 UI 证明旧默认图、上传图、编辑预览和匿名卡片正确，实际返回字节匹配。当前正式/测试候选及双构建路径复验通过，并补跨版本业务恢复；缺任何必要层级均不关闭本项。
