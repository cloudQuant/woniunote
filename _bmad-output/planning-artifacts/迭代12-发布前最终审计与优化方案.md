## 三、发现的问题与处理

### A. 发布阻断项（已在本迭代修复）

| 编号 | 问题 | 证据 | 处理 |
|------|------|------|------|
| **B1** | 前端 `npm run lint` 报 **2 个 error**：`'process' is not defined (no-undef)`，位于新增的属性测试 `src/assets/tokens.spec.js:17` 与 `src/config/themeContrast.spec.js:24`（用 `process.cwd()` 读 CSS 源文件）。CI 的 `frontend` job 跑 `eslint`，error 会**直接中断流水线**，阻断发布。 | `npm run lint` 输出；`eslint.config.js` 的 `globals` 未含 Node 全局 | 在 `eslint.config.js` 新增一段针对 `**/*.spec.js`、`**/*.config.js`、`e2e/**/*.js` 的覆盖配置，补 `process/__dirname/module/require/global/Buffer` 等 Node 只读全局。这些文件本就运行在 Node（vitest/playwright/vite）下，给 Node 全局是正确做法。修复后 `npm run lint` → **0 error**。 |

### B. 顺手清理（已在本迭代处理，低风险）

| 编号 | 问题 | 处理 |
|------|------|------|
| B2 | `src/views/Search.vue` 导入未使用的 `watch`；`src/api/index.spec.js` 导入未使用的 `afterEach`（历史遗留 warning） | 删除两处未使用导入；`npm run lint` warning 16，单测 211/211 仍全绿 |

> 说明：剩余 16 个 lint warning 绝大多数是 `catch (e) {}` 中**有意吞掉**的异常绑定（localStorage 私密模式、JSON 解析兜底等）与个别 spec 内未用变量，均非缺陷，强行改写反而增加噪音与回归面，故保留。

### C. 复核确认「已闭合、非缺陷」（无需动作）

- **上传安全**（迭代 10）：扩展名净化 `[a-z0-9]` + 白名单 + `weakly_canonical` 路径围栏（`isWithinBase`）三重防护仍在；头像文件名只由数字 userId + 净化扩展名拼接，无穿越面。✅
- **占位密钥 fail-fast**（迭代 10）：生产模式（`WONIUNOTE_ENV=prod*` 或 `app_mode=production`）下占位/空 JWT secret 抛异常拒绝启动。✅
- **JWT `sub` 防御解析**（迭代 11 F1）：`AuthFilter`/`OptionalAuthFilter` 单一咽喉做全数字校验，下游 `std::stoll` 无崩溃向量。✅
- **CORS**：`main.cc` 白名单实现，非白名单 Origin 不回 `Allow-Origin`；迭代 10 已删除会反射任意 Origin 的死代码 `CorsFilter`。✅
- **限流**：`RateLimitFilter` 用 Redis Lua 原子 `INCR+EXPIRE`，fail 策略可配（默认 fail-open）；`refresh` 端点已挂限流。✅
- **密码哈希跨平台**：Linux 用系统 `crypt_r` bcrypt；非 Linux 回退 PBKDF2-SHA256（10 万轮），`verifyPassword` 全平台识别 MD5/PBKDF2/bcrypt 三种格式，常数时间比较。✅
- **SQL**：全链路参数绑定；`CommentController` 投票列名来自固定二选一白名单（非用户输入）后拼接，安全。✅
