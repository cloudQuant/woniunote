## 一、背景与诉求

需求方原话：「分析一下当前项目是否还有什么代码质量和安全问题，如果没有了，检查一下测试覆盖率是否足够，如果测试覆盖率不足，需要补充测试覆盖率，尽可能达到 90% 以上，e2e 测试也需要，需要使用 playwright 进行端到端测试，一些重要的功能要测试到。」

迭代 10 已闭合大部分代码质量与安全问题。本迭代先做一次**新鲜复核**确认有无残留，再聚焦测试体系：前端单测覆盖率冲 90%+，并用 Playwright 补端到端测试。

## 二、代码质量与安全再审计（结论）

对活跃栈（C++ Drogon 后端 + Vue3 前端）做了一次新鲜复核，**不沿用历史勾选**：

### 实测确认已闭合（非缺陷）

- `Json::Value ret;` 残留仅存于 `ArticleController`（列表信封含分页字段，前端兼容需要）与 `UEditorController`（必须遵循 UEditor 的 `state/url` 协议）——均为**有意保留**，非缺陷。
- `std::localtime` 已在 `UploadController`/`UEditorController` 改为线程安全的 `localtime_r`/`localtime_s`。
- `std::stoll(userId)` 在 `AuthController`、`AdminFilter` 已有防御解析。

### 发现一处残留并已修复

| 编号 | 问题 | 证据 | 处理 |
|------|------|------|------|
| F1 | `AuthFilter`（所有鉴权路由的唯一咽喉）**未校验 JWT `sub` 为数字**即写入 `user_id`；其下游 6 个控制器（Favorite/Comment/User/Article/Credit/MathTraining）直接 `std::stoll(userId)` 无保护。合法签名但 `sub` 非数字的 token 会触发未捕获异常 | `filters/AuthFilter.cc`、各控制器 `std::stoll(userId)` | 在 `AuthFilter::doFilter` 与 `OptionalAuthFilter::doFilter` 增加全数字校验（与 `AdminFilter` 同款 idiom），非数字返回 401，从单一咽喉消除崩溃向量 |

> 复核结论：除 F1 外，迭代 10 声称闭合的项经实测确实闭合。F1 属防御纵深补漏，已修复并通过 C++ 构建（`-Wall -Wextra`）与 `ctest`（见第四节，补测后 29/29）。

## 三、测试覆盖率现状与目标

- 前端：`vitest` 23 用例通过，但**无覆盖率工具**；实测全量覆盖率仅 **8.82%** 语句（仅 stores/config/部分通用组件被测，逻辑层 `api/index.js`(394 行)、`utils/`、`router/` 及绝大多数视图为 0%）。

### 目标

- 用 **Playwright** 补端到端测试，覆盖重要功能流程。
- CI 加测试与覆盖率门禁。

## 四、已完成工作（迭代 11 执行结果）

> 执行日期：2026-05-31 · 前端 `vitest` **172/172 通过**，覆盖率 **98.37% 语句 / 88.06% 分支**；Playwright E2E **25/25 通过**；后端 `ctest` **29/29 通过**、主程序 `-Wall -Wextra` 构建通过。

### A. 安全补漏

- F1：`AuthFilter`/`OptionalAuthFilter` 增加 JWT `sub` 全数字校验（见上表）。

### A2. 后端 C++ 测试补充（纯逻辑可达部分）

- 新增 `tests/test_response.cc`（12 用例）覆盖 `core/response.h` 的统一响应信封：`success/ok/make` 的 `{code,message,data}` 与 200、各 error 快捷方法（`badRequest/unauthorized/forbidden/notFound/tooManyRequests/serverError`）的 HTTP 状态码与 body code 一致性、null data 不序列化、Content-Type 为 JSON、`make/error` 的 code 与 status 解耦。
- 这是迭代 10「响应统一」工作的回归护栏：前端 Axios 拦截器按 HTTP 状态分支（401/403/404/429/500），body code 与 HTTP status 若漂移会静默破坏错误处理，本组测试钉死该契约。
- 后端 C++ 测试用例数 **17 → 29**（`ctest` 多次运行稳定全绿）。

### A3. 配置 ESM 化修复

- `vitest.config.js` / `vite.config.js` 在 `"type":"module"` 下使用 `__dirname` 触发 `no-undef`/不稳健；改为 `fileURLToPath(new URL('./src', import.meta.url))`，并移除 `vite.config.js` 未使用的 `command` 解构。诊断清零，单测与 `npm run build` 均通过。

### B. 前端单元测试覆盖率：8.82% → 98.37%

### C. Playwright 端到端测试（25 用例）

- 新增 `@playwright/test` 与 `playwright.config.js`：默认 `vite build` + `vite preview` 起生产构建静态服务跑 E2E。
- **关键设计**：`e2e/support/mockApi.js` 拦截所有 `/api/**` 返回确定性 fixture（后端信封格式），使 E2E **无需** C++ 后端/MySQL/Redis，结果稳定可 CI；同时跑的是真实前端（路由守卫、渲染、store、拦截器、持久化）。`loginAs()` 注入登录态。
- 覆盖重要流程：

  | 套件 | 流程 |
  |------|------|
  | `home.spec.js` | 首页加载/列表/进详情/分类路由/404/搜索 |
  | `auth.spec.js` | 登录成功失败、注册、密码校验、已登录重定向 |
  | `protected-routes.spec.js` | 守卫：未登录拦截、管理员准入、用户中心 |
  | `article-detail.spec.js` | 详情渲染、评论、匿名收藏拦截、登录发评论 |
  | `theme-switch.spec.js` | 默认主题、切暗色、持久化、刷新保持 |
  | `user-center.spec.js` | 用户中心各子路由 |
