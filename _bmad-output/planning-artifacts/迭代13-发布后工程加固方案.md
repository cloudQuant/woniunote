## 二、各项设计与实施方案

### Epic 13.1：CI 门禁收紧

**现状**：`cpp-vue-ci.yml` 中 cppcheck `--error-exitcode=0`（不阻断）、`npm audit ... || true`（不阻断）、lint 仅 error 阻断（warning 不限）。

**目标与做法**：
- **cppcheck 转阻断**：先清理基线（`models/MathTraining.cc` 的 4 处 `useInitializationList` 性能提示，改为初始化列表），再把 `--error-exitcode=1`。
- **lint warning 阈值**：CI 的 `npm run lint` 增加 `--max-warnings=<基线>`，锁住当前 warning 数防回涨（当前 16）。本地 `package.json` 的 `lint` 保持宽松，CI 用更严格的 `lint:ci`。
- **npm audit 分级**：保留 `--audit-level=high` 但说明现状——当前唯一 high 来自 `rollup`（vite 的构建期依赖，不进运行时产物），moderate 来自 postcss 等同样为构建期。策略：尝试 `npm audit fix`（非破坏性）拉升可修复项；对无非破坏修复的构建期依赖，明确标注为「告警可见但不阻断 high 中的 dev-only」——避免因上游构建链 advisory 长期红灯。最终门禁设为：**生产依赖（`--omit=dev`）的 high/critical 阻断**，dev 依赖 advisory 仅告警。

### Epic 13.2：后端集成测试

**约束**：Drogon 控制器/DB/限流链路依赖运行时 + MySQL/Redis，单元测试不可达（迭代 11 已如实说明）。

**做法**：黑盒 HTTP 集成测试（最贴近真实、CI 可复现）：
- 新增 `backend_cpp/tests/integration/`：以独立**测试数据库**（`woniunote_test`）建表+种子，用测试配置启动已构建的后端，再用 Python（项目已有 pytest 体系）发 HTTP 请求断言关键链路：
  - `/health` 存活；
  - 注册→登录（带验证码豁免开关或 mock）→ `me`；
  - 鉴权缺失/非法 token → 401；
  - 限流触发 → 429（依赖 Redis）；
  - 统一响应信封 `{code,message,data}` 与 HTTP 状态码一致。
- 新增启动/停止脚手架脚本，保证测试 DB 与真实库隔离（**绝不动用户真实数据**）。
- 新增 CI job `backend-integration`：用 GitHub Actions 的 `services:` 起 MySQL+Redis，构建后端、灌 schema、起服务、跑集成测试。

### Epic 13.3：E2E 多浏览器矩阵

**现状**：`playwright.config.js` 仅 `chromium` 一个 project。

**做法**：
- 新增 `firefox`、`webkit` 两个桌面 project，以及一个移动端视口 project（`Pixel 5` 或 `iPhone 13` 的 `devices` 预设）。
- 用 `PW_BROWSERS` 环境变量控制本地只跑 chromium（避免强制下载全部浏览器），CI 安装并跑全矩阵。
- CI `frontend-e2e` job 改为 `playwright install --with-deps`（全部浏览器）并跑全矩阵。

### Epic 13.4：refresh token 轮换 + 复用检测

**现状**：`/api/auth/refresh` 仅校验签名/类型/用户存在，旧 refresh token 旋转后仍可用（无失效）。

**设计**（基于 Redis，与限流同款依赖）：
- token 增加 `jti`（随机唯一标识）声明；`TokenPayload` 暴露 `jti`。
- 登录与刷新时，把「当前有效 refresh jti」写入 Redis：`refresh_jti:<userId> = <jti>`，TTL = refresh 有效期。
- 刷新流程：
  - 解析 refresh token 得到 `userId` + `jti`；
  - 读 `refresh_jti:<userId>`：
    - 等于本次 `jti` → 合法 → **轮换**：生成新 access+refresh（新 jti），覆盖写 Redis；
    - 不等于（已被旋转走）→ 判定**复用攻击** → 删除 `refresh_jti:<userId>`（吊销该用户全部会话）→ 返回 401；
    - Redis 不可用 → 降级：仍签发新 token，但不做复用检测（fail-open 保可用，记 warning）。
- **权衡**：采用「每用户保留最新 jti」的单活动会话模型——在新设备刷新会使旧设备失效。对个人博客可接受，已在文档标注；如需多端并存可改为每设备 jti 集合（后续可选）。

### Epic 13.5：首屏 chunk 分割

**现状**：路由已懒加载，但 `index` 主包约 1.26MB（Element Plus + Vue 全打一起），`ArticleDetail` 约 1.53MB（PDF.js/MathJax）。

**做法**：
- `vite.config.js` 增加 `build.rollupOptions.output.manualChunks`，把 `vue`/`vue-router`/`pinia`、`element-plus`/`@element-plus/icons-vue`、`pdfjs-dist` 拆为独立 vendor chunk，提升缓存命中、降低首屏主包体积。
- 设 `build.chunkSizeWarningLimit` 合理阈值，避免 PDF.js 这类天然大库刷告警。
- 验证 `npm run build` 成功、产物分包符合预期、E2E 仍全绿（保证拆包未破坏运行时）。
