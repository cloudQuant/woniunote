## 一、背景

复核 `backend_cpp/` 当前代码后确认：迭代 8 声称的「Response 工具统一」「正确 HTTP 状态码」只覆盖了约一半控制器；同时存在上传路径穿越、CORS 双实现冲突、线程不安全调用、占位密钥可启动等问题。这些都属于**代码质量与安全**范畴，符合本次诉求，统一收口到本迭代。

本迭代聚焦五块：

1. 安全硬化补漏（上传路径穿越、占位密钥 fail-fast、refresh 限流、CORS 死代码清理）
2. 响应规范统一收口（剩余控制器迁移到 `core/response.h`，修正 HTTP 状态码）
3. 构建与并发质量（编译告警门禁、线程安全、Sanitizer 可选）
4. 上传安全加固（扩展名白名单、类型收紧、配置化）
5. 测试与 CI 安全门禁（控制器测试、依赖/静态扫描）

## 二、问题清单与现状（含证据）

### A. 安全（Security）

| 编号 | 问题 | 证据 | 现状 |
|------|------|------|------|
| A1 | 头像上传存在**路径穿越**风险：`filename = userId + ext`，`ext` 由用户文件名 `rfind('.')` 截取，未净化；形如 `a.jpg/../../x` 会污染 `saveAs` 路径 | `controllers/UploadController.cc::uploadAvatar`、`generateFilename` | 未净化扩展名 |
| A2 | 上传类型白名单过宽：`ALLOWED_FILE_TYPES` 含 `FT_CUSTOM`，`isAllowedFileType` 对 `FT_DOCUMENT` 恒真；且上传目录即 `document_root`，静态可直出 | `UploadController.cc` 顶部集合 + `config.json` `document_root=./uploads` | 可能存储型 XSS/任意类型落盘 |
| A3 | 占位密钥可正常启动：`jwt_secret=CHANGE_ME...`、db `passwd=CHANGE_ME...` 仅打 warning 不阻断 | `core/config.cc`（仅 `Logger::warning`）、`config.json` | 生产可能带占位密钥运行 |
| A4 | `refresh` 端点**无限流**，登录/注册已挂 `RateLimitFilter`，刷新令牌可被刷 | `controllers/AuthController.h`（refresh 无 filter） | 暴力刷新无护栏 |
| A5 | `CorsFilter.cc` 仍反射任意 `Origin` 且 `Allow-Credentials: true`（`origin.empty()?"*":origin`），与 `main.cc` 的白名单实现冲突 | `filters/CorsFilter.cc`；`CMakeLists.txt` `FILTER_SOURCES` **未包含** CorsFilter | 死代码，误接即漏洞 |
| A6 | Redis 无密码（`passwd:""`），限流/缓存依赖的 Redis 在非本机部署时裸奔 | `config.json` `redis_clients` | 仅本机安全 |

## 三、迭代目标

1. 关闭上传路径穿越与类型过宽风险；占位密钥在生产模式 fail-fast；refresh 挂限流；清理 CORS 死代码。
2. 把剩余控制器全部迁到 `core/response.h`，错误响应一律带正确 HTTP 状态码；`AuthController` 收口到统一 Response。
3. 后端开启编译告警门禁与可选 Sanitizer；消除 `localtime` 等线程不安全调用；`stoll` 加防御解析。
4. 上传体积/类型配置化 + 扩展名白名单。
5. CI 增加安全门禁（依赖审计 + C++ 静态分析），补关键控制器/安全路径测试。

## 四、分阶段任务（Epic 拆解）

### Epic 10.1：安全硬化补漏（P0，约 1 sprint）

- [ ] A1：上传文件名净化——扩展名只保留 `[A-Za-z0-9]` 且白名单校验，剥离路径分隔符；`generateFilename`/`uploadAvatar` 共用净化函数，落盘前 `weakly_canonical` 校验最终路径在上传根目录内。
- [ ] A2：上传类型收紧——去掉 `FT_CUSTOM`，对图片/文件分别用扩展名 + MIME 双白名单；评估给上传静态目录加 `Content-Disposition: attachment` 或独立非可执行目录。
- [ ] A3：占位密钥 fail-fast——新增 `app_mode`/环境判定，生产模式下 JWT secret 为占位/空或 db 占位密码时**拒绝启动**（dev 仅告警）。
- [ ] A4：`refresh` 端点挂 `RateLimitFilter`；评估 refresh token 轮换/复用检测（如旋转后旧 token 失效）。
- [ ] A5：删除 `filters/CorsFilter.{cc,h}`（未编译的死代码），或在文件头明确标注废弃并从仓库移除，避免误接。
- [ ] A6：`config.prod.json` 要求 Redis 设置密码；文档补充 Redis/DB 凭据下发说明。

### Epic 10.2：响应规范统一收口（P1，约 1 sprint）

- [ ] B1：将 `FavoriteController`、`SystemController`、`UserController`、`UploadController`、`CaptchaController`、`MathTrainingController`、`ThumbController`、`UEditorController` 全量改用 `core/response.h`。
- [ ] B2：随迁移修正所有错误响应 HTTP 状态码（400/401/403/404/429/500），与前端 `api/index.js` 拦截器分支对齐。
- [ ] B3：`AuthController` 移除自带 `makeJsonResponse/makeErrorResponse`，统一到 `Response`。

### Epic 10.3：构建与并发质量（P1，约 0.5 sprint）

- [ ] C1：`CMakeLists.txt` 增加 `-Wall -Wextra -Wpedantic`（非 MSVC），清理由此暴露的告警。
- [ ] C2：新增 `ENABLE_SANITIZERS` 选项（ASan+UBSan），用于本地/CI 测试构建。
- [ ] B4：`std::stoll(userId)` 改防御解析（`try/catch` 或先校验全数字），失败返回 401。
- [ ] B5：`UploadController` 的 `localtime` 改 `localtime_r`（或 Drogon 时间工具），消除数据竞争。

### Epic 10.4：上传配置化（P2，约 0.5 sprint）

- [ ] B6：图片/文件/头像体积上限与允许类型迁入 `custom_config`，`Config` 暴露读取接口，控制器消费配置而非魔法值。

### Epic 10.5：测试与 CI 安全门禁（P2-P3，持续）

- [ ] C3：CI 显式 `-DBUILD_TESTING=ON` 并跑 `ctest`；测试构建启用 Sanitizer。
- [ ] C4 / D1 / D2：CI 增加 `npm audit`（阈值门禁）+ 前端 ESLint；后端接入 `clang-tidy` 或 `cppcheck`（先告警不阻断，再逐步收紧）。
- [ ] E1 / E2：补关键控制器与安全路径测试——上传扩展名净化、`refresh` 限流、`stoll` 防御、占位密钥 fail-fast、统一 Response 状态码断言。
- [ ] D2：前端关键依赖锁定（去 `^` 或加 lockfile 校验）。
