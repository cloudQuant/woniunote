## UEditor 支持 PDF / PPT 在线阅读方案设计

本文档说明如何在当前 woniunote 项目中，让 UEditor 编辑器支持 **导入 PDF / PPT 文档，并在文章中直接阅读**。  
UEditor 本质是一个富文本编辑器，最终存储的是 **HTML 内容**，因此我们需要做的是：在上传完文档之后，生成一段可以在线预览的 HTML 片段，并把它插入到编辑器内容中即可。

---

### 总体思路

1. 在 UEditor 上新增「插入文档」入口（支持 PDF / PPT）。  
2. 用户选择本地文件后，通过后端上传接口把文件上传到服务器。  
3. 后端返回一个「可预览 URL」以及必要的元数据。  
4. 前端在 UEditor 中插入一段占位 HTML（例如一个带自定义 data-* 属性的 `<div>` 或 `<iframe>`）。  
5. 文章详情页渲染时，前端识别这些占位元素，并根据类型加载对应的在线预览组件（浏览器原生、PDF.js、图片轮播等）。

---

### 方案一：浏览器原生 PDF 预览（推荐作为起步方案）

**思路**

- 对于 PDF：现代浏览器基本都内置 PDF 查看能力，可以通过 `<iframe>` / `<embed>` / `<object>` 直接打开。  
- 对于 PPT：浏览器原生不支持，通常需要插件，体验和可靠性都不好，不建议直接依赖。更好的方式是「PPT 转 PDF 再预览」。

**前端插入示例（在 UEditor 里插入 HTML）：**

```html
<!-- PDF 预览 -->
<iframe
  src="https://your-site.com/uploads/sample.pdf"
  style="width: 100%; height: 600px; border: none;"
></iframe>
```

**优点**

- 实现成本极低，UEditor 无需大改，仅需插入一段 HTML。  
- 性能开销小，依赖浏览器原生 Viewer。  
- 完全自托管，不依赖外部服务。

**缺点**

- 仅适合 PDF，PPT 需要先转换。  
- 不同浏览器 PDF 预览界面不一致，对 UI 控制有限。  
- 若需要登录访问控制，需要从文件 URL / 接口层面做鉴权。

**结论**

- **推荐：PDF 先采用方案一，作为实现的第一步。**  
- PPT 通过后端转换为 PDF 后，同样走这个方案。

---

### 方案二：引入 PDF.js 等前端 PDF 查看器（更佳体验）

**思路**

- 在前端（Vue）中集成一个 PDF 查看器组件（如 `pdf.js` WebViewer）。  
- 上传 PDF 后，后端仍返回文件 URL。  
- 在 UEditor 内容中插入一个占位元素，例如：

```html
<div class="doc-viewer" data-type="pdf" data-src="/uploads/sample.pdf"></div>
```

- 文章详情页渲染完成后，Vue 代码扫描 `.doc-viewer` 元素，根据 `data-type` / `data-src` 动态挂载 `PdfViewer` 组件，内部使用 `pdf.js` 渲染。

**优点**

- 统一的预览 UI，交互可控（翻页、缩放、目录等）。  
- 不依赖浏览器内建插件，兼容性可控。  
- 更易于做权限控制与埋点统计。

**缺点**

- 接入复杂度高于方案一：  
  - 需要自定义前端组件。  
  - 需要定义文章内容里的占位符约定。  
- 引入 `pdf.js` 会增加前端包体积。

**结论**

- 如果对文档阅读体验要求较高，可以在方案一稳定之后，升级为方案二。  
- 实现路径：**先打通上传 + iframe 预览，再逐步替换为 pdf.js 组件。**

---

### 方案三：使用在线文档服务（Google Docs / Office Online 等）

**思路**

- 上传文档后，拿到公网可访问的文件 URL。  
- 使用外部服务的在线预览地址进行嵌入，例如：

```html
<!-- Google Docs 示例 -->
<iframe
  src="https://docs.google.com/gview?embedded=true&url=https://your-site.com/uploads/sample.pdf"
  style="width: 100%; height: 600px; border: none;"
></iframe>
```

**优点**

- 无需自己实现文档渲染，直接享受成熟的查看器能力，特别适合 PPT/Office 文档。  
- 预览效果通常较好。

**缺点**

- 强依赖外部服务：网络、稳定性、访问限制都不可控。  
- 存在隐私/合规风险：文档需要公网可访问。  
- 部分服务有调用频率或授权限制。

**结论**

- 不建议作为生产长期方案，可用于内部环境或 PoC 快速验证。

---

### 方案四：PPT 转图片 + 图片轮播展示

**思路**

- 后端将 PPT/PPTX 转换为一组 PNG/JPG 图片（例如借助 LibreOffice、unoconv 等）。  
- 上传后返回图片列表 URL。  
- 在 UEditor 中插入一个占位容器，例如：

```html
<div class="ppt-viewer" data-images='["/uploads/ppt1_page1.png","/uploads/ppt1_page2.png"]'></div>
```

- 文章详情页中前端解析 `data-images`，使用轮播组件展示幻灯片。

**优点**

- 兼容性极好，只依赖图片展示能力。  
- 排版还原度通常较高。  
- UI 可完全自定义。

**缺点**

- 交互性有限：无法复制文字，无法搜索。  
- 图片体积可能较大。  
- 需要在后端部署文档转换工具。

**结论**

- 适合 PPT 数量较多、主要用于视觉展示场景。  
- 可以与 PDF.js 方案配合使用：Office -> PDF -> 图片 / PDF，按需选择展示方式。

---

### 与 UEditor 集成的通用步骤

无论选择哪种预览方案，和 UEditor 的结合大致分为四步：

1. **扩展 UEditor 工具栏按钮**
   - 新增「插入文档」按钮，触发文件选择和上传逻辑。  
   - 可参考已有的「插入图片」或「插入视频」插件实现。

2. **后端上传接口设计**
   - 接收文件（PDF / PPT / PPTX）。  
   - 将文件存储到统一的上传目录或对象存储。  
   - 对于 PPT：可选步骤是先转换为 PDF 或图片，再返回对应的 URL / 元数据。  
   - 返回结构建议包含：
     - `url`: 可访问地址  
     - `type`: `pdf` / `ppt` / `ppt-converted`  
     - 其他元信息（标题、页数等，可选）

3. **在编辑器中插入占位 HTML**
   - 对于简单方案（浏览器 PDF 预览），可以直接插入 `<iframe>`。  
   - 对于需要前端组件渲染的方案，插入标准化的占位符（`<div class="doc-viewer" ...>` / `<div class="ppt-viewer" ...>`）。

4. **文章详情页渲染逻辑**
   - 页面加载完成后，Vue 代码扫描文档占位元素：  
     - 对于 `<iframe>`：无需额外处理。  
     - 对于 `doc-viewer` / `ppt-viewer`：动态挂载对应的 Vue 组件进行渲染。  
   - 注意在 SPA 路由切换时正确销毁/重建查看器组件。

---

### 推荐实施路径（结合当前项目）

1. **第一阶段：快速支持 PDF 预览**
   - 后端实现 PDF 上传接口，返回文件 URL。  
   - UEditor 新增「插入 PDF」按钮：上传后直接向内容中插入 `<iframe>`。  
   - 验证在文章详情页中可以滚动阅读 PDF。

2. **第二阶段：支持 PPT（通过转换）**
   - 在后端部署 PPT -> PDF 转换能力。  
   - 上传 PPT 时自动转换为 PDF，返回 PDF URL。  
   - 前端沿用与 PDF 相同的插入逻辑。

3. **第三阶段（可选）：引入 PDF.js 优化阅读体验**
   - 添加 `PdfViewer` 组件，逐步将 iframe 替换为 `doc-viewer` 占位符 + 组件渲染方式。  
   - 提供统一的 UI 和更丰富的交互（缩放、目录等）。

通过上述三个阶段，可以从**低成本可用**逐步演进到**高质量体验**，同时让 UEditor 与现有后端、前端架构平滑集成。
